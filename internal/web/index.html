Placement

Records = (size + overhead) × records × RF × (1 + growth) × compression × (1 + write-block overhead), on device or in memory (7.0+ write blocks); the RAM ceiling of a memory namespace is the weighted harmonic mean of the RAM fill (indexes) and the storage fill (records). Primary index in RAM = 64 B per copy; on flash, 4 KiB sprigs holding 64 entries at the fill share (partition-tree-sprigs rounded up to a power of two between 256 and 256M, × 4096 partitions × RF, plus 5 B of roots per sprig), with 10 B of RAM each. Secondary indexes = entries × 14 B × sparseness × RF; set indexes = 16 B per copy. CPU = (reads/s + writes/s) × (1 + growth) ÷ transactions per vCPU. Device IOPS, in 4 KiB blocks = [writes/s × RF × stored size ÷ 4 KiB × defrag whenever records reach a device (they fill 8 MiB write blocks: the device writes their bytes) + reads/s × reads that find a record × (1 − cache hit) × ⌈stored size ÷ 4 KiB⌉ with the device engine, when there are records of some bytes (the blocks a record spans; a read that finds nothing stops at the primary index, though it costs CPU and network like any read), plus one flash index read per read and a read and a write per replica write with the index on flash] × (1 + growth), where stored size = (size + overhead) × compression; counted in 4 KiB blocks, they bound the device bandwidth too. Growth applies to the records and to the throughput alike, replication traffic included. Nodes per resource = demand ÷ what a node offers at its ceiling on the nodes left after the planned loss, plus the lost nodes, never fewer than RF+1, rounded up so that every rack holds as many nodes.

Rates are the fully-loaded cost per GB moved between the AZs of a region: AWS bills both directions ($0.01/GB each way, 0.02), Google Cloud egress only ($0.01 per GiB, entered here per GB), Azure nothing since May 2024 (0). Read on ; check the current billing of your provider.

Rates are the cost per GB shipped between regions, billed on egress by every provider: 0.02 per GB (AWS, Azure) or per GiB (Google Cloud) between two regions of the same continent, more for other pairs. Read on ; check the current billing of your provider.

Cost comparison

Each provider's recommended configuration for the workload, which follows the form: among the instance types offered in the region chosen below, the one with the lowest reference price on the basis chosen below, plus 2 % per node so that dozens of small nodes do not win over a sensible cluster, at the node count that keeps every load under 85 % of the usable capacity (the rule Aerospike Wellness applies too); then the configurations you add. arm64 marks the types with Arm processors (AWS Graviton, Google Axion). A configuration that is tight or short gets, when one exists, the cheapest instance type that fits comfortably with as many nodes. Changing the nodes of a recommendation keeps it as entered.
